## Decisions

Use the existing 600-second minimum long-turn idle contract as the default, retaining ten minutes for expensive silent work and two hours overall. This is an operational default, not a claim about provider latency. Existing explicit environment/dashboard overrides remain effective. No new knob is needed.

HTTP headers and subsequent transport reads share the effective idle allowance. The bridge retains its existing narrow 60-second response-created guard and separate bounded pre-response queue policy. Direct WebSocket response-start silence is bounded by the same effective idle allowance as post-start silence. Keepalives generated by LB do not prove upstream activity. Received HTTP body bytes or WebSocket application/lifecycle frames renew the read-idle allowance without requiring model tokens. Protocol ping/pong liveness is separate; an application stream with no such activity still reaches the configured idle bound. Overall remaining budget is never reset.

Carry aiohttp.ClientTimeout into CodexClient, which already supports its separate native and Python timeout parts. Remove the first-event HTTP idle-timeout-only failover branch, which replayed delivery-ambiguous work on another account. Retain all independent proven retry and owner fences. Local timeout alone does not authorize account failover or health penalties.

## Risks and limits

An upstream that remains completely silent for over ten minutes now terminates by default. Operators can retain a longer explicit idle value. A connection that continues upstream activity may run until the unchanged total deadline. No incident causation or installed behavior is inferred.
