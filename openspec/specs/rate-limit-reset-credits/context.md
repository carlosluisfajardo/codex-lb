# rate-limit-reset-credits context

Dashboard consume accepts expectedCreditId and expectedCreditExpiresAt for first-selection and retry custody, and checks the authoritative durable pin before admission. SQLite claim expiry/renewal uncertainty stops the owning body; cancellation after acquisition commit still releases the exact holder. Cancellation of an already-sent upstream consume leaves an unknown outcome and retains its request pin. Local same-process controlled evidence does not establish external at-most-once consumption or installed multi-process behavior.

Renewal first performs an exact-holder no-op update to obtain the write lock and the current old deadline. It checks UTC time after that await, retains full stored microsecond precision, and holds the lock through extension and commit or rollback. A second check after the extension statement rolls back if the old deadline elapsed during that await. Concurrent heartbeat and admission renewals serialize on this lock. No database transaction/statement NOW() assumption is used. PostgreSQL endpoint redemption retains its existing transaction advisory lock rather than the SQLite lease path; no PostgreSQL runtime qualification is claimed by the private SQLite tests.

Dashboard and automatic redemption re-read the account through the supplied database session after serialization and after the final pre-consume claim renewal. The real SELECT refreshes the session identity map; it rejects missing/pending-deletion rows, changed local/upstream identity and the existing non-redeemable statuses. For example, a pause committed while the request waits for its predecessor prevents credential/upstream work; a pause during the fresh credit fetch prevents consume. A routing hold is independent and remains compatible with reset redemption. Sessionless helper callers retain caller-owned state rather than acquiring an implicit database session.

These checks observe committed state at their database read boundary. They do not lock the account across the external request or make credit spending atomic with a later pause, deletion or identity change. A request pinned before a late refusal retains that pin, with the existing finite lifetime and unknown-outcome reconciliation semantics. Private SQLite/ASGI tests prove the local waiting cases; they do not establish PostgreSQL isolation behavior, external spending outcomes, or installed behavior. Reset discovery and request-pin lifetime are unchanged.

For SQLite, the final renewal returns its exact holder ID. The subsequent final SELECT joins the account with the current claim holder and expiry, so a claim loss during that read is not hidden by an earlier successful renewal. Both account eligibility and observed ownership are checked after this single await; full-precision UTC expiry is compared with the clock then, with no further await before consume admission. Tests expire the real private claim or acquire it as a successor while the final read is suspended, alongside valid-holder eligible/held controls. Cleanup preserves the successor and the durable request pin. This is a joint admission observation, not an account/claim lock spanning provider I/O: mutations after the database snapshot and expiry after admission remain outside that boundary. The existing heartbeat still supervises the body; cancellation after upstream dispatch retains an unknown outcome.
